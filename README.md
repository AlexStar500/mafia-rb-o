# МАФИЯ · Ночной город

Атмосферная браузерная мафия без сборщика и фреймворков: ванильный JavaScript, ES-модули, мобильный интерфейс, живые комнаты, умные боты, роли, ночной чат, музыка и режим наблюдателя.

Клиент полностью статический — его можно положить на GitHub Pages. Для игры между устройствами добавлен маленький WebSocket-relay на Node.js: он передаёт только небольшие JSON-кадры и ничего не знает о ролях.

---

## Что внутри

- **4–20 игроков**, настраиваемый минимум для старта.
- **Роли:** Мафия, Шериф (Комиссар), Мирный, Доктор, Ассасин, Шут.
- **Мафия видит своих** и общается в закрытом ночном чате.
- **Доктор** не может лечить одного игрока две ночи подряд; самолечение — один раз за игру.
- **Ассасин** со второй ночи один раз пробивает лечение контрактом.
- **Шут** побеждает только если его повесили; в игре он максимум один.
- **Голосование** по большинству: минимум 2 голоса, ничья никого не вешает.
- **Тренировка с ботами**, **наблюдение за ИИ-городом** (пауза, 1×/2×/4×).
- **Быстрый старт**, браузер комнат, вход по коду, приглашения ссылкой.
- **Порты** — комнаты через `BroadcastChannel`: несколько вкладок одного браузера, без сервера.
- **Локальная сеть** — `npm start` на компьютере, друзья открывают его LAN-адрес. Игра и relay живут в одном процессе, как LAN-сервер в CS2.
- **Онлайн-комнаты** через relay — разные устройства и сети; при запуске через `npm start` адрес relay определяется сам.
- **Быстрый чат** из 64 канонических фраз в два шага: сначала фраза, потом адресат.
- **Боты** с именами вымышленных ИИ (Cloud, Seafin, Qiri, Gemmi…) и разным уровнем сообразительности: слышат друг друга, отвечают на «Привет», понимают простые вопросы, обвинения и заявки на роль.
- **Музыка** день/ночь: ночь — зацикленный эмбиент, день — ваншот без лупа.
- **PWA-оболочка**: манифест, service worker, офлайн-запуск после первого визита.
- **Тёмный нуар** — слоновая кость, золото, багровый, дождь, туман, силуэт города.
- **Мобильный first**: нижний док, safe-area, тач-размеры, отсутствие горизонтального скролла от 320 px.

## Быстрый старт

Нужен Node.js 18.17+.

```bash
npm install
npm start
```

Откройте <http://localhost:8080>. Тот же процесс поднимает relay на `ws://localhost:8080/ws` и печатает LAN-адреса вида `http://192.168.x.x:8080/` — по ним друзья заходят в режиме «Локальная сеть».

Другие команды:

```bash
npm run dev      # сервер с --watch
npm test         # 30 тестов движка, протокола, relay, роутера и сессий
npm run check    # синтаксис + тесты
npm run relay    # отдельный relay на порту 8787
npm run art      # перегенерировать ASCL-арт (Python + Pillow)
node scripts/sim.mjs  # прогон партии из 9 ботов в консоли
```

### Режимы

| Режим | Как открыть | Сеть |
| --- | --- | --- |
| Тренировка | Главная → «Играть», свободные места занимают боты | не нужна |
| Наблюдение | Главная → «Смотреть ИИ-город» | не нужна |
| Порты | Создать → «Порты», затем вторая вкладка → «Комнаты» | `BroadcastChannel`, один браузер |
| Локальная сеть | `npm start` → открыть `http://<LAN-IP>:8080/` → «Локальная сеть» | WebSocket на компьютере-хосте |
| Онлайн | Создать → «Онлайн», указать relay или запустить relay на том же адресе | WebSocket, интернет |

«Порты» — это комнаты между вкладками одного браузерного профиля: сервер не нужен, данные идут через `BroadcastChannel`. Другие устройства их не видят — это ограничение технологии, а не баг.

«Локальная сеть» — режим в духе CS2: вы запускаете `npm start` на компьютере, консоль показывает LAN-адрес (`http://192.168.x.x:8080/`), друзья открывают его в той же сети. Приложение и relay работают на одном порту, поэтому ничего настраивать не нужно. Ссылка-приглашение ведёт прямо на компьютер-хост.

«Онлайн» — тот же relay, но доступный из интернета: VPS, Render, Railway или Cloudflare Tunnel. На GitHub Pages и `mafia.rb-o.ru` сервер не запускается, поэтому для онлайн-игры нужен внешний relay. Если страница уже открыта с сервера приложения, клиент сам проверяет `/health` и подставляет `ws://<текущий-адрес>/ws`.

## GitHub Pages

1. Запушьте репозиторий на GitHub (ветка `main`).
2. **Settings → Pages → Build and deployment → Source: GitHub Actions**.
3. Workflow `.github/workflows/pages.yml` прогонит тесты и выложит только статические файлы: `index.html`, `404.html`, `css/`, `js/`, `assets/`, `sw.js`, `manifest.webmanifest`, иконки.
4. Игра откроется по адресу `https://<user>.github.io/<repo>/`.

Базовый путь определяется автоматически (`js/ui/router.js`, `detectBasePath`), поэтому проект работает и в корне домена, и в подпапке. Ссылки-приглашения ведут на `/join?code=…` и учитывают базу.

### Свой домен

В репозитории лежит `CNAME` с `mafia.rb-o.ru`; workflow копирует его в артефакт. В GitHub: **Settings → Pages → Custom domain → `mafia.rb-o.ru`**, затем включите **Enforce HTTPS**. У DNS-провайдера настройте `A`-записи на IP GitHub Pages или `CNAME` поддомена на `<user>.github.io`. После смены домена базовый путь становится корнем (`/`), а старые ссылки на `/<repo>/` продолжают работать благодаря автоопределению базы. При смене домена поднимите `VERSION` в `sw.js`, чтобы клиенты сбросили старый кэш.

GitHub Pages не умеет SPA-fallback, поэтому «красивые» адреса (`/join`, `/room/ABC234`, `/rooms`) загружаются в два шага: `404.html` переводит их на настоящий корень с маркером (`/?code=…`, `/?room=…`, `/?route=rooms`), а приложение сразу возвращает адрес через `history.replaceState`. Так относительные CSS/JS всегда грузятся из корня проекта. Dev-сервер делает то же самое через 302, а service worker перехватывает глубокие переходы до сети — включая офлайн-режим. Прямой `/room/CODE` открывает экран входа, потому что сессию нельзя восстановить после перезагрузки. Неизвестный адрес без расширения получает маркер `?notfound=…` и показывает встроенный экран 404, а не молча отправляет на главную; отсутствующие файлы (`*.js`, `*.png`) остаются настоящими 404.

**GitHub Pages не запускает Node.js.** Для онлайн-комнат нужен отдельный relay.

## Relay

Relay — это тупой транспорт:

- принимает `create` / `join` / `relay` / `meta` / `kick` / `close`;
- хранит только публичные метаданные комнаты (название, число игроков, код);
- пересылает кадры между хостом и гостями;
- **не получает роли, ночные действия и закрытые чаты** — их считает хост и отправляет персонализированные снимки состояния.

### Запуск на своём компьютере

```bash
npm run relay
# ws://localhost:8787/ws, список комнат: http://localhost:8787/rooms
```

### Переменные окружения

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `RELAY_PORT` или `PORT` | `8787` | Порт HTTP/WebSocket |
| `RELAY_HOST` | `0.0.0.0` | Интерфейс |
| `RELAY_ALLOWED_ORIGINS` | пусто (любой) | Список origin через запятую, например `https://user.github.io` |
| `TRUST_PROXY` | `0` | `1`, если relay стоит за доверенным reverse-proxy и нужно брать IP из `X-Forwarded-For` |

В production обязательно задайте `RELAY_ALLOWED_ORIGINS` и поставьте HTTPS.

### Nginx + systemd (VPS)

```nginx
server {
    listen 443 ssl http2;
    server_name mafia.example.com;

    location / {
        proxy_pass http://127.0.0.1:8787;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_read_timeout 70s;
    }
}
```

```ini
[Unit]
Description=MAFIA relay
After=network.target

[Service]
WorkingDirectory=/opt/mafia
ExecStart=/usr/bin/node server/relay-standalone.mjs
Environment=RELAY_PORT=8787
Environment=RELAY_ALLOWED_ORIGINS=https://user.github.io
Environment=TRUST_PROXY=1
Restart=always

[Install]
WantedBy=multi-user.target
```

В настройках игры или при создании онлайн-комнаты укажите `wss://mafia.example.com/ws`. Адрес можно передать в ссылке-приглашении параметром `relay`.

Relay также запускается на Render/Railway/Fly.io как обычный Node-сервис: платформа сама передаст `PORT`.

## Архитектура

```text
index.html              оболочка, CSP, атмосфера, док, точка входа
css/                    токены, база, компоненты, экраны, адаптив
js/
  core/                 события, random, sanitization, storage, format
  data/                 роли и баланс, боты, фразы, быстрый чат
  game/                 host-authoritative GameEngine и мозги ботов
  net/                  протокол, auto (поиск relay), local (BroadcastChannel), online (WS), сессии, комнаты
  screens/              menu, quick, rooms, create, join, lobby, game, roles, rules, settings
  ui/                   DOM-шаблоны, иконки, модалки, тосты, чат, формы, роутер
server/                 dev-сервер и relay (не нужны на GitHub Pages)
scripts/                генерация арта ASCL, консольная симуляция
test/                   node:test: движок, relay, сессии
assets/                 PNG-арт, музыка OGG/MP3, исходные ASCL
sw.js                   офлайн-кэш статики
```

### Хост — единственный источник правды

Хост держит `GameEngine`, таймеры, роли, голоса и чат. Каждому клиенту уходит **персонализированный** снимок: чужие роли скрыты, мафия видит только своих, мёртвые видят то, что им разрешено. Relay не может утечь роли, потому что никогда их не получает.

Клиентские ID уникальны для вкладки, устройство хранит только настройки профиля. Игровое состояние и чат живут в памяти; после закрытия вкладки комната исчезает, а `?mode=solo` / `?mode=spectate` намеренно не восстанавливаются после перезагрузки.

### Чат, мёртвые и быстрый чат

- Каналы: `public` (город), `mafia` (живая мафия ночью), `dead` (погибшие), системные события.
- Живые игроки читают `public`, мафия ночью — ещё и `mafia`. Погибшие видят чат живых, включая ночной канал мафии, и свой `dead`; писать могут только в `dead` (и последним словом в `public`). Роль и закрытые договорённости не утекают наблюдателям.
- Быстрый чат двухшаговый: сначала каноническая фраза, затем адресат. Фразы от третьего лица (`{name} ведёт себя странно`) требуют цели; движок проверяет, что цель существует, жива и не совпадает с автором. В чате мёртвых цель тоже должна быть мёртвой.
- Свободный текст ограничен скользящим окном: около 6 сообщений за 10 секунд и короткие паузы между ними. Это защита от флуда, а не лимит на разговор за фазу.
- Последние слова пишутся в `dead` и видны погибшим; живые их не получают.
- Список комнат показывает комнаты в портах сразу, не дожидаясь ответа relay, и подгружает остальные страницами по 8 («Показать ещё»).

## Безопасность

- Строгий CSP-meta: `script-src 'self'`, без inline-скриптов и inline-обработчиков.
- Весь пользовательский текст проходит через экранирующий `html`; ник, чат и название комнаты санитизируются.
- Быстрый чат передаёт **ID канонической фразы**, а не доверенный текст.
- Ограничения длины кадров, размера комнаты, числа соединений с IP, token-bucket на сообщения.
- Allowlist origin для relay, проверка протокола relay-URL, запрет `javascript:` и credentials в URL.
- Защита от path traversal в dev-сервере, range-запросы для аудио, `nosniff`, `frame-ancestors 'none'`.
- Рекомендуемые заголовки на статическом хостинге: HSTS, `X-Content-Type-Options`, `Referrer-Policy`.

CSP находится в `index.html`. Если добавляете внешний шрифт, CDN или аналитику — расширяйте политику осознанно.

## Роли и баланс

Состав считается в `js/data/roles.js`:

- Шериф — всегда один.
- Мафия — примерно `floor((n + 2) / 4)`, но не больше 5.
- Ассасин заменяет одного мафиози с 8 игроков.
- Доктор доступен с 5 игроков.
- Шут — с 7 игроков, максимум один.
- Остальные — мирные.

Настройки комнаты: максимум игроков, минимум для старта, публичность, доктор/ассасин/шут, таймеры ночи/обсуждения/голосования, активность ботов, раскрытие роли после смерти, наблюдатели.

## Арт и музыка

- 6 иконок ролей, 20 портретов ботов и бренд-иконки — настоящее пиксель-арт 24×24, увеличенное ×8 до 192×192 (бренд — до 512).
- Исходники ASCL лежат в `assets/ascl/`.
- Регенерация: `python scripts/generate_art.py` (нужны Python 3, Pillow и путь к `ascl.py`; путь задаётся константой `ASCL` в начале скрипта).
- Музыка: `assets/audio/day.ogg|mp3`, `assets/audio/night.ogg|mp3`. Исходные WAV-файлы остаются в корне проекта и не участвуют в деплое.
- SFX синтезируются Web Audio API, отдельных файлов нет.

Если меняете треки, перекодируйте их в OGG и MP3, сохраните имена и обновите версию в `sw.js`, чтобы service worker не отдавал старый кэш.

## Ограничения

- GitHub Pages не запускает relay; онлайн-игра требует отдельный Node-хост (или режим «Локальная сеть»).
- Комнаты в портах не работают между разными браузерами или устройствами.
- Для «Локальной сети» компьютер-хост должен быть включён, а порт `8080` — доступен в локальной сети (брандмауэр Windows может спросить разрешение).
- GitHub Pages на HTTPS не может открыть `ws://` к частному адресу; LAN-ссылка поэтому ведёт на `http://<LAN-IP>:8080/`, а не на GitHub Pages.
- Нет аккаунтов и серверной истории: это осознанно, состояние живёт в памяти.
- Service worker кэширует статику; после релиза поднимите `VERSION` в `sw.js`, чтобы клиенты обновились.
- Музыка и арт принадлежат автору проекта; не публикуйте их отдельно без разрешения.
