# МАФИЯ · Ночной город

Атмосферная браузерная мафия без сборщика и фреймворков: ванильный JavaScript, ES-модули, мобильный интерфейс, живые комнаты, умные боты, роли, ночной чат, музыка и режим наблюдателя.

Клиент полностью статический: его можно выложить на любой статический хостинг. Для игры между устройствами есть два транспорта: HTTP-relay на Vercel-функции (`/api`, короткий опрос — работает без WebSocket) и маленький WebSocket-relay на Node.js для локальной сети или VPS. Оба передают только небольшие JSON-кадры и ничего не знают о ролях.

---

## Что внутри

- **4–25 игроков**, настраиваемый минимум для старта.
- **Роли:** Мафия, Ассасин, Бармен, Шпион, Шериф, Доктор, Судья, Музыкант, Мирный, Шут, Кукловод, Близнец.
- **Мафия видит своих** и общается в закрытом ночном чате. Бармен и Шпион играют за мафию, но не видят её состав и ночной чат — писать туда они могут.
- **Доктор** не может лечить одного игрока две ночи подряд; самолечение — один раз за игру.
- **Ассасин** со второй ночи один раз выполняет контракт: цель умирает даже через лечение, а сам ассасин погибает, если его не вылечат в ту же ночь.
- **Судья** один раз за игру днём казнит выбранного игрока; если тот не мафия, погибает сам судья.
- **Музыкант** ночью блокирует чужое действие, дневную способность и голос на следующий день.
- **Шут** побеждает только если его повесили. **Кукловод** выбирает марионетку и побеждает вместе с её командой. **Близнецы** (ровно двое) не знают друг друга: смерть одного забирает второго, а казнь одного приносит победу выжившему.
- **Голосование** по большинству: минимум 2 голоса, ничья никого не вешает.
- **Тренировка с ботами**, **наблюдение за ИИ-городом** (пауза, 1×/2×/4×).
- **Быстрый старт**, браузер комнат, вход по коду, приглашения ссылкой.
- **Порты** — комнаты через `BroadcastChannel`: несколько вкладок одного браузера, без сервера.
- **По IP** — `npm start` у хоста, остальные заходят по его адресу с кодом комнаты. С пробросом порта подключаются из любого города.
- **Онлайн-комнаты** через HTTP-relay на Vercel (`/api`) или WebSocket-relay; при запуске через `npm start` адрес relay определяется сам.
- **Быстрый чат** из 76 канонических фраз в два шага: сначала фраза, потом адресат или роль.
- **Боты** с именами вымышленных ИИ (Cloud, Seafin, Qiri, Gemmi…) и разным уровнем сообразительности: слышат друг друга, отвечают на «Привет», понимают простые вопросы, обвинения и заявки на роль.
- **Музыка** день/ночь: обе темы зациклены, а короткий ваншот отмечает рассвет.
- **PWA-оболочка**: манифест, service worker, офлайн-запуск после первого визита.
- **Тёмный нуар** — слоновая кость, золото, багровый, дождь, туман, силуэт города.
- **Мобильный first**: нижний док, safe-area, тач-размеры, отсутствие горизонтального скролла от 320 px.

## Быстрый старт

Нужен Node.js 18.17+.

```bash
npm install
npm start
```

Откройте <http://localhost:8080>. Тот же процесс поднимает relay на `ws://localhost:8080/ws` и печатает адреса вида `http://192.168.x.x:8080/` — по ним друзья заходят в режиме «По IP».

Другие команды:

```bash
npm run dev      # сервер с --watch
npm test         # тесты движка, протокола, relay, роутера и сессий
npm run check    # синтаксис + тесты
npm run relay    # отдельный relay на порту 8787
npm run art      # перегенерировать ASCL-арт (Python + Pillow)
node scripts/sim.mjs  # прогон партии из 9 ботов в консоли
```

### Режимы

| Режим | Как открыть | Сеть |
| --- | --- | --- |
| Тренировка | Главная → «Играть», свободные места занимают боты | не нужна |
| Наблюдение | Главная → «Смотреть ИИ-город» | не нужна |
| Порты | Создать → «Порты», затем вторая вкладка → «Комнаты» | `BroadcastChannel`, один браузер |
| По IP | `npm start` → открыть `http://<IP>:8080/` → «По IP» | WebSocket на компьютере-хосте |
| Онлайн | Создать → «Онлайн»; адрес `https://…` (Vercel) или `wss://…` (Node) | HTTP-опрос или WebSocket, интернет |

«Порты» — это комнаты между вкладками одного браузерного профиля: сервер не нужен, данные идут через `BroadcastChannel`. Другие устройства их не видят — это ограничение технологии, а не баг.

«По IP» — это игра по локальной сети: вы запускаете `npm start` на компьютере, консоль показывает адрес (`http://192.168.x.x:8080/`), друзья открывают его и вводят код комнаты. Приложение и relay работают на одном порту. Для игроков из других городов нужен проброс порта `8080` на роутере или туннель до этого адреса — тогда хостом может быть любой компьютер с интернетом, а не только сосед по Wi-Fi.

«Онлайн» — это relay, доступный из интернета. Vercel используется только для HTTP-функции `/api`: игра остаётся статической и может жить на GitHub Pages, а клиент сам проверяет `/api/health` и включает короткий опрос. Для WebSocket-режима подойдёт VPS, Render или Railway: если страница открыта с сервера приложения, клиент сам проверяет `/health` и подставляет `ws://<текущий-адрес>/ws`. Адрес можно ввести вручную в настройках или при создании комнаты.

## Публикация

1. Запушьте репозиторий на GitHub (ветка `main`).
2. **Settings → Pages → Build and deployment → Source: GitHub Actions**.
3. Workflow `.github/workflows/pages.yml` прогонит тесты и выложит только статические файлы: `index.html`, `404.html`, `css/`, `js/`, `assets/`, `sw.js`, `manifest.webmanifest`, иконки.
4. Игра откроется по адресу `https://<user>.github.io/<repo>/`.

Любой другой статический хостинг тоже подходит: достаточно отдать те же файлы и настроить fallback на `404.html`.

### Vercel: только relay для комнат

Сама игра — статический сайт, её домен остаётся прежним (GitHub Pages / `mafia.rb-o.ru`). Vercel нужен только как HTTP-relay, чтобы у онлайн-комнат был адрес `/api` без WebSocket-сервера. Сборка не нужна: в проекте лежат `vercel.json` и функция `api/index.mjs`.

```bash
npx vercel link      # выбрать проект mafiarbovercel
npx vercel deploy --prod
```

Проверка: `https://mafiarbovercel.vercel.app/api/health` возвращает `{"ok":true,"service":"mafia-relay","http":true,"protocol":2,…}`, а `/api/rooms` — список публичных комнат.

Клиент уже знает публичный адрес (`PUBLIC_HTTP_RELAY` в `js/net/auto.js`): если у страницы нет своего `/api`, онлайн-режим сам подключается к Vercel. Дополнительно проверяется `relay.mafia.rb-o.ru` — это тот же проект на своём поддомене, он выручает, когда сеть не пускает edge-IP `*.vercel.app`. Поэтому игру можно держать на GitHub Pages, а Vercel использовать только для комнат. Свой relay можно указать вручную в настройках или в ссылке-приглашении.

Чтобы включить поддомен, добавьте в Cloudflare запись `CNAME relay → 519c7b8516c7e157.vercel-dns-017.com` (или `cname.vercel-dns.com`) в режиме **DNS only**. Домен уже добавлен в проект Vercel; после появления записи `/api/health` ответит и на `https://relay.mafia.rb-o.ru`.

Комнаты хранятся в памяти тёплого инстанса функции. Для дружеских партий этого хватает; при большой аудитории подключите Redis/Upstash за теми же маршрутами, иначе разные инстансы не увидят комнаты друг друга.

Базовый путь определяется автоматически (`js/ui/router.js`, `detectBasePath`), поэтому проект работает и в корне домена, и в подпапке. Ссылки-приглашения ведут на `/join?code=…` и учитывают базу.

### Свой домен

В репозитории лежит `CNAME` с `mafia.rb-o.ru`; workflow копирует его в артефакт. В GitHub: **Settings → Pages → Custom domain → `mafia.rb-o.ru`**, затем включите **Enforce HTTPS**. У DNS-провайдера настройте `A`-записи на IP GitHub Pages или `CNAME` поддомена на `<user>.github.io`. После смены домена базовый путь становится корнем (`/`), а старые ссылки на `/<repo>/` продолжают работать благодаря автоопределению базы. При смене домена поднимите `VERSION` в `sw.js`, чтобы клиенты сбросили старый кэш.

Открытие по `http://` на публичном домене автоматически переводится на HTTPS (`js/https-redirect.js`). Исключения — `localhost`, голые IP-адреса, `.local` и IPv6: у них обычно нет сертификата, и редирект сломал бы игру по локальной сети.

GitHub Pages не умеет SPA-fallback, поэтому «красивые» адреса (`/join`, `/room/ABC234`, `/rooms`) загружаются в два шага: `404.html` переводит их на настоящий корень с маркером (`/?code=…`, `/?room=…`, `/?route=rooms`), а приложение сразу возвращает адрес через `history.replaceState`. Так относительные CSS/JS всегда грузятся из корня проекта. Dev-сервер делает то же самое через 302, а service worker перехватывает глубокие переходы до сети — включая офлайн-режим. Прямой `/room/CODE` открывает экран входа, потому что сессию нельзя восстановить после перезагрузки. Неизвестный адрес без расширения получает маркер `?notfound=…` и показывает встроенный экран 404, а не молча отправляет на главную; отсутствующие файлы (`*.js`, `*.png`) остаются настоящими 404.

**Статический хостинг сам по себе не запускает Node.js.** Публичный HTTP-relay для комнат живёт на Vercel (`/api`), а для WebSocket-режима нужен отдельный Node-хост.

## Relay

Relay — это тупой транспорт:

- принимает `create` / `join` / `relay` / `meta` / `kick` / `close`;
- хранит только публичные метаданные комнаты (название, число игроков, код);
- пересылает кадры между хостом и гостями;
- **не получает роли, ночные действия и закрытые чаты** — их считает хост и отправляет персонализированные снимки состояния.

Есть две реализации с общим смыслом кадров:

- **HTTP** (`api/index.mjs`) — для Vercel и любого хостинга функций. Клиент опрашивает `/api/rooms/:code/events` примерно раз в 650 мс, POST-запросы уходят из очереди по одному, чтобы порядок кадров не терялся.
- **WebSocket** (`server/relay.mjs`) — для `npm start`, «По IP» и VPS.

HTTP-маршруты (все под `/api`):

| Метод | Путь | Назначение |
| --- | --- | --- |
| `GET` | `/health` | проверка relay |
| `GET` | `/rooms` | публичные комнаты |
| `POST` | `/rooms` | создать комнату |
| `POST` | `/rooms/:code/join` | войти гостем |
| `GET` | `/rooms/:code/events` | забрать события с курсора |
| `POST` | `/rooms/:code/events` | отправить кадр хосту или гостю |
| `POST` | `/rooms/:code/meta` | обновить метаданные (хост) |
| `POST` | `/rooms/:code/kick` | исключить гостя (хост) |
| `POST` | `/rooms/:code/close` | закрыть комнату (хост) |
| `POST` | `/rooms/:code/leave` | выйти из комнаты |

### Запуск на своём компьютере

```bash
npm run relay
# ws://localhost:8787/ws, список комнат: http://localhost:8787/rooms
```

### Переменные окружения

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `RELAY_PORT` или `PORT` | `8787` | Порт HTTP/WebSocket |
| `RELAY_HOST` | `0.0.0.0` | Интерфейс |
| `RELAY_ALLOWED_ORIGINS` | пусто (любой) | Список origin через запятую, например `https://game.example.com` |
| `TRUST_PROXY` | `0` | `1`, если relay стоит за доверенным reverse-proxy и нужно брать IP из `X-Forwarded-For` |

В production обязательно задайте `RELAY_ALLOWED_ORIGINS` и поставьте HTTPS.

### Nginx + systemd (VPS)

```nginx
server {
    listen 443 ssl http2;
    server_name mafia.example.com;

    location / {
        proxy_pass http://127.0.0.1:8787;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_read_timeout 70s;
    }
}
```

```ini
[Unit]
Description=MAFIA relay
After=network.target

[Service]
WorkingDirectory=/opt/mafia
ExecStart=/usr/bin/node server/relay-standalone.mjs
Environment=RELAY_PORT=8787
Environment=RELAY_ALLOWED_ORIGINS=https://game.example.com
Environment=TRUST_PROXY=1
Restart=always

[Install]
WantedBy=multi-user.target
```

В настройках игры или при создании онлайн-комнаты укажите `wss://mafia.example.com/ws`. Адрес можно передать в ссылке-приглашении параметром `relay`.

Relay также запускается на Render/Railway/Fly.io как обычный Node-сервис: платформа сама передаст `PORT`.

### Хост — единственный источник правды

Хост держит `GameEngine`, таймеры, роли, голоса и чат. Каждому клиенту уходит **персонализированный** снимок: чужие роли скрыты, мафия видит только своих, мёртвые видят то, что им разрешено. Relay не может утечь роли, потому что никогда их не получает.

Клиентские ID уникальны для вкладки, устройство хранит только настройки профиля. Игровое состояние и чат живут в памяти; после закрытия вкладки комната исчезает, а `?mode=solo` / `?mode=spectate` намеренно не восстанавливаются после перезагрузки.

### Чат, мёртвые и быстрый чат

- Каналы: `public` (город), `mafia` (живая мафия ночью), `dead` (погибшие), системные события.
- Живые игроки читают `public`, мафия ночью — ещё и `mafia`. Погибшие видят чат живых, включая ночной канал мафии, и свой `dead`; писать могут только в `dead` (и последним словом в `public`). Роль и закрытые договорённости не утекают наблюдателям.
- Быстрый чат двухшаговый: сначала каноническая фраза, затем адресат. Фразы от третьего лица (`{name} ведёт себя странно`) требуют цели; движок проверяет, что цель существует, жива и не совпадает с автором. В чате мёртвых цель тоже должна быть мёртвой.
- Свободный текст ограничен скользящим окном: около 6 сообщений за 10 секунд и короткие паузы между ними. Это защита от флуда, а не лимит на разговор за фазу.
- Последние слова пишутся в `dead` и видны погибшим; живые их не получают.
- Список комнат показывает комнаты в портах сразу, не дожидаясь ответа relay, и подгружает остальные страницами по 8 («Показать ещё»).

## Безопасность

- Строгий CSP-meta: `script-src 'self'`, без inline-скриптов и inline-обработчиков.
- Весь пользовательский текст проходит через экранирующий `html`; ник, чат и название комнаты санитизируются.
- Быстрый чат передаёт **ID канонической фразы**, а не доверенный текст.
- Ограничения длины кадров, размера комнаты, числа соединений с IP, token-bucket на сообщения.
- Allowlist origin для relay, проверка протокола relay-URL, запрет `javascript:` и credentials в URL.
- Защита от path traversal в dev-сервере, range-запросы для аудио, `nosniff`, `frame-ancestors 'none'`.
- Рекомендуемые заголовки на статическом хостинге: HSTS, `X-Content-Type-Options`, `Referrer-Policy`.

CSP находится в `index.html`. Если добавляете внешний шрифт, CDN или аналитику — расширяйте политику осознанно.

## Роли и баланс

Состав считается в `js/data/roles.js`:

- Шериф — всегда один.
- Мафия — примерно `floor((n + 2) / 4)`, но не больше 5 и не больше половины города.
- Ассасин, Бармен и Шпион входят в команду мафии; рядом с ними всегда остаётся хотя бы один обычный мафиози.
- Доктор, Судья, Музыкант, Шут, Кукловод и Близнецы настраиваются поштучно; Близнецы добавляются только парой.
- Остальные — мирные; как минимум один мирный остаётся всегда, лишние роли снимаются с предупреждением в интерфейсе.

Настройки комнаты: максимум игроков, минимум для старта, публичность, количество каждой роли, таймеры ночи/обсуждения/голосования, активность ботов, раскрытие роли после смерти, наблюдатели.

## Арт и музыка

- 12 иконок ролей, 20 портретов ботов и бренд-иконки — настоящее пиксель-арт 24×24, увеличенное ×8 до 192×192 (бренд — до 512).
- Исходники ASCL лежат в `assets/ascl/`.
- Регенерация: `python scripts/generate_art.py` (нужны Python 3, Pillow и путь к `ascl.py`; путь задаётся константой `ASCL` в начале скрипта). `--new-roles` пересобирает только иконки Бармена, Шпиона, Судьи, Музыканта, Кукловода и Близнеца.
- Музыка: `assets/audio/day-loop.ogg|mp3` (день, луп) и `assets/audio/night.ogg|mp3` (ночь, луп), плюс короткий `day.ogg|mp3` на рассвет. Исходные WAV-файлы остаются в корне проекта и не участвуют в деплое.
- SFX синтезируются Web Audio API, отдельных файлов нет.

Если меняете треки, перекодируйте их в OGG и MP3, сохраните имена и обновите версию в `sw.js`, чтобы service worker не отдавал старый кэш.

## Ограничения

- Статическая версия сама по себе не запускает relay: для публичных комнат используется HTTP-функция на Vercel, а для WebSocket — отдельный Node-хост (или режим «По IP»).
- HTTP-relay хранит комнаты в памяти инстанса функции. Тёплый инстанс обслуживает дружескую партию, но при нескольких инстансах или холодном старте комната может пропасть — для масштаба нужен Redis/Upstash.
- Комнаты в портах не работают между разными браузерами или устройствами.
- Для «По IP» компьютер-хост должен быть включён, а порт `8080` — доступен (брандмауэр Windows может спросить разрешение). Для игроков из других городов нужен проброс порта на роутере или туннель.
- HTTPS-страница не может открыть `ws://` к частному адресу; ссылка «По IP» поэтому ведёт на `http://<IP>:8080/`.
- Нет аккаунтов и серверной истории: это осознанно, состояние живёт в памяти.
- Service worker кэширует статику; после релиза поднимите `VERSION` в `sw.js`, чтобы клиенты обновились.
- Музыка и арт принадлежат автору проекта; не публикуйте их отдельно без разрешения.
